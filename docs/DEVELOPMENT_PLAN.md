# Android rtp2httpd 开发计划

本文件是后续开发的任务清单与验收依据。目标是在现有 Android 转发服务上增加局域网 HTTP 管理网页和持久化 YAML 配置，同时保留现有启动方式与默认参数。

状态约定：`[x]` 表示对应实现或指定检查已经完成；`[ ]` 表示待开发或待验证。代码存在、主机测试通过、机顶盒实测通过分别记录，不能互相替代。

## 1. 当前基线

- [x] ARM64、最低 Android 8.0/API 26 的无 Activity 前台服务，ADB shell/root 通过 DUMP 权限调用。
- [x] 五个现有参数：upstream_interface、listen_interface、port、maxclients、verbose；workers 固定为 1。
- [x] 参数通过独立 argv 传入，核心使用 --noconfig，不执行用户拼接的 shell 命令。
- [x] SharedPreferences 保存启动参数，START_STICKY 系统回收恢复。
- [x] 核心退出和网卡暂不可用时退避重试，主动停止取消重试并释放 CPU/组播锁。
- [x] 固定上游 v3.17.2 / ec7808b813d4595dff890713993bc46b82f72fc2，并完成 NDK Android ARM64/API 26 编译。
- [x] Android/Bionic 适配：epoll、跳过 librt、私有临时路径、BSD 字符串函数替换、API 26 的普通发送路径、原生父进程死亡处理入口。
- [x] SDK/R8 Release 打包与核心 ELF、哈希、许可证、zipalign 检查；约 478 KiB 的未签名 APK 含 629248 字节原生核心。
- [x] 构建只检查已有工具、跨 SDK 复用 NDK，并选择包含 Android 34 和 Build Tools 35.0.0 的完整打包 SDK；缺少环境时停止并提示，不自动安装。
- [x] 12 项 JVM 测试和 20 项构建脚本测试已有通过记录。
- [ ] 完整 Gradle Debug/Release/lint 任务图验证。
- [ ] 安装、真实 IPTV 转发、进程树清理和机顶盒长时间运行验收。
- [ ] 项目根目录 Git 首次提交。main 已建立且文件已暂存，但没有提交；当前会话写 .git/index.lock 被拒绝，使用标准 Git 命令完成首次提交。
- [ ] HTTP 配置服务、管理网页和 YAML 存储尚未实现。

## 2. 产品与架构约束

1. 继续面向长期通电的机顶盒，无需 Android Activity、触屏交互或手机电池优化申请流程。
2. 在同一个 APK、现有前台服务宿主内提供 HTTP 管理能力；不为保活额外启动第二个 Android Service。
3. 管理 HTTP 的生命周期独立于原生核心。核心启动失败、停止转发或等待重试时，管理页面仍可用。
4. 管理端口建议默认 5141，流媒体转发端口保留 5140。两个端口不得冲突。
5. 保留不启用管理功能时的 ADB 使用方式。第一版管理功能须显式启用，并配置管理监听地址与访问令牌，避免现有升级突然增加管理入口。
6. YAML 是 Android 封装层的配置格式。第一版解析后生成受控 argv，保留核心 --noconfig；不修改原生核心来解析 YAML。上游原生 INI 配置作为后续兼容能力另列。
7. 配置、状态与核心控制都经过统一的配置模型和生命周期控制器；网页、ADB、系统恢复不各自维护一套参数拼装逻辑。
8. 页面静态资源内置 APK，不依赖 CDN；第一版使用简单表单和文本编辑器，适合电脑与手机浏览器。
9. 保持轻量。HTTP/YAML 依赖在实现前核对体积、许可证、Android/API 26 兼容性和维护成本，不手写冒充完整 YAML 的解析器。
10. 不提供任意可执行路径、shell 命令执行或任意文件编辑接口。
11. 环境准备只检查与提示，不自动安装、升级、卸载或修改使用者的 SDK、JDK、包管理器及永久环境配置；构建输出与默认工具缓存留在项目目录。

## 3. 配置契约

### 3.1 默认值与优先级

- 保留 port=5140、maxclients=5、verbose=2、workers=1；未指定 listen_interface 时监听所有 IPv4 地址。
- upstream_interface 没有可靠的跨设备默认值，不硬编码 eth0。有保存配置时恢复；首次启用管理功能但尚未配置网卡时，仅启动管理页等待配置。
- 启动合并顺序为：内置默认值 → 已保存 YAML → 本次实际传入的 Intent 字段。
- 只有 Intent.hasExtra 为真的字段才覆盖保存配置，防止 getIntExtra 的默认值覆盖用户保存的端口等参数。
- 网页“保存并应用”以提交后的完整配置为新的运行目标，覆盖当前临时覆盖值；后续新的显式 ADB 启动仍可再次覆盖。
- 系统空 Intent 恢复使用最近一次成功应用的配置，不能退回过期的 SharedPreferences。
- 主动停止整个服务后不得因为保存了配置而自动启动；停止转发与停止整个服务是两种不同动作。

### 3.2 建议的第一版 YAML 结构

下例是计划中的 schema 示例，不代表当前应用已经支持。

```yaml
schema_version: 1

management:
  enabled: true
  listen_address: 192.168.1.100
  port: 5141
  # 访问令牌由首次授权启动设置，私有保存，不回显在普通配置导出中。

relay:
  enabled: true
  upstream_interface: eth0
  listen_interface: wlan0
  port: 5140
  maxclients: 5
  verbose: 2
  workers: 1
```

- [ ] 为每个字段定义类型、默认值、边界、是否允许空值及错误消息；拒绝未知字段和不支持的 schema_version。
- [ ] YAML 使用安全数据模式；不允许对象构造、任意类型标签及外部文件引用，限制输入大小、嵌套深度与别名扩展。
- [ ] 导出的公开配置与本地保存的有效配置使用同一 schema，管理凭据独立存储；凭据字段不接受普通配置 API 读取。
- [ ] 对网卡暂不可用与配置本身非法分别处理，保留已有网络恢复重试能力。
- [ ] 定义启动配置、已保存配置、待应用配置与当前实际运行配置的区别；页面明确显示未应用修改。

### P2：管理 HTTP 与服务状态控制

- [ ] `HTTP-01` 在现有前台服务中增加独立的管理 HTTP 监听器，支持配置管理地址/端口，区分管理端口和转发端口。
- [ ] `HTTP-02` 管理监听不依赖核心成功启动；未配置上游网卡、核心缺失、核心退出和重试时仍可访问配置/状态页。
- [ ] `HTTP-03` 定义显式启用管理功能的 ADB extra；兼容未启用时原有行为。首次授权启动设置令牌，不能启用无认证的管理写入口。
- [ ] `HTTP-04` 管理 API 使用独立凭据，网页会话不将令牌放入 URL、日志或普通配置导出；限制失败尝试。
- [ ] `HTTP-05` 防止跨站写操作，验证 Origin/Host 与会话，禁用开放式 CORS；限制请求体、请求头、读取超时和并发数。
- [ ] `HTTP-06` 统一管理 STOPPED、WAITING_CONFIG、STARTING、RUNNING、RETRY_WAIT、APPLYING、ERROR 等状态，单一控制通道串行修改核心状态。
- [ ] `HTTP-07` 核心停止、启动、重试和新配置应用互斥；旧进程结束前不得启动替代进程，旧退出回调不得停止新实例。
- [ ] `HTTP-08` 提供有界日志缓冲与最近错误；限制内存和响应大小，敏感字段脱敏。
- [ ] `HTTP-09` 主动停止整个 Android 服务时关闭管理端口、取消队列/重试、清理进程并释放锁；单独停止转发时保留管理入口。
- [ ] `HTTP-10` 管理地址/端口修改单独处理：成功绑定新监听器后再切换，失败保留旧入口；页面显示新地址，避免普通转发参数修改导致失联。

第一版 API 草案，路径可在实现时统一命名，语义须保持：

| 接口 | 用途 |
| --- | --- |
| GET / | 返回内置管理页面 |
| POST /api/session、DELETE /api/session | 建立/退出管理会话 |
| GET /api/status | 管理/核心状态、版本、运行配置 revision、重试时间及最近错误 |
| GET /api/interfaces | 网卡名称、地址与可用状态，供选择网卡 |
| GET /api/config | 读取脱敏配置与 revision |
| POST /api/config/validate | 校验候选 YAML，不持久化、不重启 |
| POST /api/config/apply | 带 revision 提交并应用候选配置 |
| GET /api/config/export | 导出不包含管理凭据的 YAML |
| POST /api/config/rollback | 明确恢复上一份可用配置 |
| POST /api/relay/start、stop、restart | 控制转发核心，管理页保持可用 |
| GET /api/logs | 读取有界、脱敏的最近日志 |

除静态登录页与创建会话所需入口外，管理 API 均鉴权；未认证状态不能读取日志、网卡详情或配置。

验收：核心崩溃和非法配置不会导致管理页退出；停止转发仍能修改配置；停止整个服务后无监听端口和重试；未授权和跨站请求不能读取敏感信息或修改配置。

### P3：配置应用、回滚与恢复

- [ ] `APPLY-01` 完成“读取 → 编辑 → 校验 → 暂存 → 应用 → 提交有效配置”的流程，不将解析成功当作运行成功。
- [ ] `APPLY-02` 实现候选配置启动检测、超时与失败判定；启动失败时恢复上一份可用配置，并保留失败原因给管理页。
- [ ] `APPLY-03` 为暂存、上次成功和当前应用状态保存必要元数据，覆盖写入中断、核心退出、Java 被杀和系统重建的恢复顺序。
- [ ] `APPLY-04` 首版对转发参数采用受控重启；保存前提示应用将中断当前转发连接，不承诺无缝热重载。
- [ ] `APPLY-05` 防止回滚和自动重试形成无限切换；失败状态可见，用户可手动修复或停止转发。
- [ ] `APPLY-06` 保持原有 START_STICKY、CPU 锁续租和网卡恢复行为；管理页空闲时不意外启动已被主动停止的核心。
- [ ] `APPLY-07` 迁移后 YAML 成为持久配置来源，清理重复的 SharedPreferences 读写路径，管理凭据和必要恢复元数据除外。

验收：端口占用、网卡无地址、核心启动后立即退出、保存时断电等情况下，管理入口可达，已保存与实际运行状态可区分，能够回滚到上一份可用配置。

- [ ] `WEB-02` 登录及会话错误提示，不把凭据持久化到地址栏或默认可导出的 YAML。

- [ ] `WEB-04` 常用参数表单与网卡选择，提供字段范围、当前值和默认值提示。

验收：局域网浏览器可完成首次配置和后续修改，无需修改盒子文件；网络错误有明确反馈，失败后仍能回到管理页；页面不依赖外网资源。
