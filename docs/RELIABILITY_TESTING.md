# 机顶盒长期运行验证

已完成原生核心编译和 Release 打包，以下转发验收须在实际机顶盒上进行。普通 APK 无法保证进程永不被杀；本次实现提供前台运行、CPU 唤醒、系统回收后的参数恢复及核心退出后的重试。

## 本地自动检查

使用 JDK 17：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease
```

JVM 测试使用可控的子进程替身覆盖配置与并发行为，并在支持 `/bin/sleep` 的主机验证真实子进程停止；不代替 Android 组件、系统调度或 rtp2httpd 原生进程验证。

## 设备验收

安装 Debug APK，通过 README 命令指定盒子真实网卡启动。用 `adb logcat -s Rtp2httpd` 观察运行情况，播放器持续拉取真实 IPTV 流。

1. **重复启动**：再次启动同一服务，即使传不同参数，也只能保留原核心和原配置；等待重试时也不能创建第二个重试循环。
2. **临时网络缺失**：使用尚未出现的网卡启动，通知应显示等待重试，日志记录递增间隔。网卡恢复并拥有 IPv4 后应自动启动核心。确认每次尝试都重新读取网卡地址。
3. **核心退出**：用 Debug 包的 `run-as` 或设备 root 权限向核心 supervisor 发信号。确认先观察到退出，再按 1、2、4、8、16、32、60 秒重试；每次只允许一个有效 supervisor/worker 集合。连续运行 60 秒后再次终止，下一次重试应回到 1 秒。
4. **系统回收恢复**：在可调试/root 测试盒子中模拟杀死 Java 宿主进程，保留 Android 服务的已启动记录。不要用“强行停止”或 `am stopservice` 模拟系统回收。确认系统重新创建服务后使用保存的网卡、端口、并发数及日志级别，无需重新发送参数。系统不保证恢复延迟。
5. **主动停止**：分别在运行、等待重试、正在启动时执行 `adb shell am stopservice -n local.rtp2httpd/.RelayService`。至少观察 70 秒，不应出现新核心或重试；端口释放，CPU/组播锁释放。通过 dumpsys power、dumpsys wifi 核对锁状态。再显式启动需传完整参数。
6. **休眠与长跑**：保持机顶盒通电，分别熄屏/待机并持续拉流，验证 CPU 锁续租后仍能转发；长跑至少 24 小时，记录内存、丢包、端口与进程数。
7. **错误与停止边界**：非法数值参数、缺失核心、保存配置不存在或不可读时应停止，不得无限重试。用户强行停止后不得自动拉起；重启盒子后不应自行启动。

## 原生核心接入时必须补验的边界

- Java 宿主被 SIGKILL 时不会调用 onDestroy，直接子进程和 fork 出的 worker 是否随宿主结束必须实测；不能假定本次 Java 层清理解决了这个问题。
- supervisor 的正常终止必须能回收全部 worker；超时强制终止 supervisor 时也要检查 worker、socket 和锁文件。
- supervisor 退出而 worker 残留时，不应因重试积累进程或一直占用监听端口。必要时在原生侧补充父进程死亡处理和进程组清理。
- 本次没有实现核心仍存活时的流量健康检测、网络切换重绑、开机自启或绕过用户强行停止。

## 当前环境的验证限制

本次环境不允许写入用户 Gradle 缓存；改用临时缓存目录后，Gradle 仍因无法创建本地文件锁通信 socket 而停止。ADB 服务也无法绑定本地监听端口。因此完整 Gradle 任务和盒子测试尚未完成；采用项目专用 `--sdk-only` 路径完成了真实 APK 打包。

已有通过记录：JDK 17 下 12 项 JUnit 测试（包括真实主机子进程停止）、20 项构建脚本测试（含 SDK 选择、缺少环境不安装且不先拉源码的检查）、Android API 34 引导类路径下的 Java 8 编译、NDK ARM64/API 26 编译、R8 Release 优化打包、ELF/包内容/核心哈希及 zipalign 检查。未运行完整 Gradle lint 或 Android 设备测试。
